# Languages

FundaCAD's text lives in one file per language, `src/i18n/locales/<code>.json`. English (`en.json`) is complete
by definition and is the fallback for every line. Each other shipped language holds every English line, machine
translated until a person reviews it. How a user picks a language and corrects a line is in the manual
(`manual/docs/reference/preferences.md`); this page is for contributors.

Saved files, the engine, MCP tools and their schema, the start question window and the manual stay English. So do
the tests: a test that never calls `initLanguage` sees English, and the harness `Session` and `e2e/docs_shots.cjs`
run the browser in `en-US`.

## Show a line

1. Add the line to `src/i18n/locales/en.json`, keeping the file sorted by key, two space indented, with a newline at
   the end. `tests/i18n/locales.test.ts` checks the format.
2. Add the same key, translated, to every other file in `src/i18n/locales/`. Machine translation is fine (see
   Wording below); a shipped language that misses a line fails the tests.
3. Show it with `t()`, imported by name:

```ts
import { t } from "../../i18n";

t("stress.setup.addLoad");
t("stress.faces.count", { n: faces.length });
```

The key's type is made from `en.json` (`MessageKey` in `src/i18n/index.ts`), so a key with no English line fails
`npm run typecheck`, in templates as well as in TypeScript. Write keys as literals, never build one
(`` t(`stress.dir.${d}`) ``), since a built key escapes that check; a table maps a value to its key, as `AXIS_KEYS`
in `src/ui/stress.ts` does. A key no source names in quotes fails the tests, so when the code stops asking for a
line, remove it from every file.

`t()` reads the chosen language reactively: a template or a `computed` shows the new text the moment the language
changes. A table built once when its module loads does not. Give its labels a getter, as `option()` in
`src/ui/stress.ts` does, or build the list in a `computed`. Text drawn outside Vue, on a canvas or in a menu built
once, listens with `onLanguageChange`.

`tEnglish()` gives the English line whatever the language, for a name that stays stable, such as the alias the command
palette also matches. A user language file cannot change it.

## Keys

- `area.thing` or `area.thing.detail`, each part a lowercase letter then letters and digits: `prefs.language.hint`,
  `stress.setup.forceDirection`. The area is the feature or panel.
- The same English in two places keeps two keys, another language may need two different words.
- Keys are the API of every user's own language file. A typo or wording fix keeps the key. A changed meaning gets a
  new key, so a translation of the old meaning falls back to English instead of saying the wrong thing. A user's
  line for a key that no longer exists is listed as skipped, never fatal.

## Messages

Lines use a small part of ICU MessageFormat (`src/i18n/format.ts`), never pasted strings, so each language puts its
words in its own order and forms its own plurals.

| Form | Example | Notes |
|---|---|---|
| Value | `{body} (not on the current model)` | Shown as given. A missing one shows as `{body}`, so it is seen |
| Number | `{missing, number} not found` | Formatted for the language, never grouped: `210000` |
| Plural | `{n, plural, =0 {No faces} one {# face} other {# faces}}` | `#` is the count. Options `zero one two few many other` and `=N`, `other` required |
| Choice | `{reason, select, markup {holds markup} other {not used}}` | Any word as an option, `other` required |

```json
{
  "stress.faces.count": "{n, plural, one {# face} other {# faces}}",
  "stress.faces.missingSome": "{n, plural, one {# face} other {# faces}}, {missing, number} not found on the current model"
}
```

Each language fills the plural options its own way: French reads 0 as `one`, Chinese and Japanese need only `other`.
A translation may leave out a value English uses, never add one English lacks. An apostrophe quotes: `'{'` shows a
brace and `''` one apostrophe, while an apostrophe before a letter stays as it is, so `l'appui` needs no doubling.

A number shown beside a value box is passed as text, spelled with `spellNumber` or `spellRounded` from
`src/ui/measure.ts` so it matches the box, not as `{n, number}`, so a panel never shows `0.35` beside a box that reads
`0,35`. Counts and prose take `{n, number}` and plurals.

## Numbers

The decimal mark comes from the active language's tag, read once through `Intl.NumberFormat` by `decimalMarkOf` in
`src/i18n/format.ts` and asked as `decimalMark()` from `src/i18n/index.ts`: a comma for `de`, `fr`, `es`, `pl` and
`de-AT`, a point for `en`, `zh-CN`, `ja` and `de-CH`. A tag the runtime does not know gives a point, so an own file
never follows the PC's locale by accident. Nothing is grouped.

Typing follows it. In a language with a decimal comma every comma in a box or an expression is the decimal mark, so
`1,5`, `1,500` and `0,125` read as 1.5, 1.5 and 0.125, and a point works as well: `1.5`. `1.234,5` and `1,5,5` are
refused, never guessed, and so is a lone point before exactly three digits after a nonzero whole part, `1.500` or
`12.000`, which could be a thousands point: the mirror of `1,000` in English. `0.250`, `.500`, `1.50`, `1.5000` and
`1.500e3` keep their point reading, since no thousands point follows a zero. Where a pair of numbers shares one box, such as the sketch point box, the pair takes a
semicolon: `20;10`. In a language with a decimal point a lone comma keeps its old reading (`1,5` is 1.5, `1,500` and
`0,125` are refused as ambiguous). `canonicalTyping(raw, mark)` in `src/ui/measure.ts` does the reading, with
`commasToPoints` in `src/params/decimalForm.ts` for the comma mark. A box that takes only a plain number reads it with
`plainNumber(raw)` in `src/ui/units.ts` by the same rules, and plugins get it from the host. A test that needs a comma
language calls `await setLanguage("de")` and restores it with `afterEach(() => setLanguage("system"))`.

Showing follows it too. A value box spells its number with `spellNumber(n)` in `src/ui/measure.ts`, which is `String(n)`
with the point swapped for the mark, so English output is byte for byte what it was and the minus stays ASCII.
`spellRounded(v)` rounds as `roundForDisplay` does first, and `formatMeasure` spells through the same function.
`spellFixed(v, digits)` is `toFixed` with the mark, trailing zeros kept, for a readout with fixed decimals. `roundForDisplay`, `toUnit` and `displayValue` still return numbers, because a box steps and compares with them. Plugins
get `numberText` from the host. A box that compares its text, such as a settings number or `NumberField`, compares the
spelled text, and a number typed back as shown reads as that exact value. A native range input always takes a point,
so only the readout beside it and its `aria-valuetext` carry the comma.

Readouts follow the mark as well: `fmtLength`, `fmtArea`, `fmtLengthCompact`, `fmtGridStep` and the spoken lengths in
`src/ui/units.ts` spell through it, so a screen reader hears `0,35`. A list of numbers is joined with `listJoin(parts)`,
which uses `; ` in a comma language and `, ` otherwise, because `12,5, 3` cannot be read. A box that takes a typed list
splits it the same way, as the Extra Parameters choices box reads `Small = 2,5; Large = 30` in Deutsch, and plugins get
`listJoin` and `decimalMark` from the host for it. Text drawn outside Vue, such as
the viewport, redraws on `onLanguageChange` beside its `onUnitChange`.

Files never change with the language. An expression typed with a decimal comma is saved with a point:
`storedExpr(typed)` in `src/ui/measure.ts` turns the commas of its numbers into points. It reads typed text only: in a
comma language it throws `ExprError` on `1.500`, so it must never run on stored text, and calling it twice is not
harmless. `typedExprProblem(typed)` returns that refusal as a string for a box to show. It is called where a person's text is handed to the document: the value box of a
feature (`FeatureProperties`), the sketch dimension editor (`evalDimInput`), a tool's value box (`typedExpr` in
`dimInput.ts`), the Parameters dialog (add and both Expression columns) and the Extra Parameters checks. Plugins get it
from the host. The store, `src/params/parse.ts`, the engine and MCP never convert: a `param_set` from an assistant reads the same
in every language, so `1,5` is refused in Deutsch as it is in English. A missed edge fails safe, the tokenizer refuses
the comma and nothing wrong is stored.
The way back is `shownExpr(stored)`, also from the host: every box, title and tooltip that shows saved expression text
goes through it, and a box that takes the text back (the Parameters Expression columns, the feature value box, the sketch
dimension editor and list, the checks of Extra Parameters) is read by `storedExpr` again. `pointsToCommas` in
`src/params/decimalForm.ts` finds the number tokens with the tokenizer, so names, units and `;` stay, a point with no digit
after it (`5.`) stays, and text that does not tokenize is shown as saved. `storedExpr(shownExpr(e))` is `e` for every
expression of `tests/vectors/params.json`.

## Text, never markup

A line is text. Never put a `t()` result in `innerHTML`, `v-html` or any other HTML sink, set `textContent` or use a
template. A user's language file is untrusted, so lines with tags or entities are refused, but the sink is the real
guard.

## Values are not labels

Translate what is shown, never what is saved or compared. An option's value stays as it is (`"Custom"`, `"fixed"`),
only its label goes through `t()`. Material names (`PA12 nylon`, `steel S235`), default feature names (`Box`) and any
other name that lands in a document stay English. `tests/i18n/stressSetup.test.ts` checks that a study set up in
German equals the English one; a panel that saves what it shows wants the same test.

## Tool names

The ribbon tables in `src/ui/ribbonDefs.ts` and the tool rail they feed speak the language. `tool()` and `split()` give
each item a `label` getter that reads `t()` when it is used, so a language switch updates the rail without a rebuild.
Never spread or copy a tool item, the copy freezes its label. `tool()` also records the action's key in `TOOL_KEYS`,
and `toolLabel(action)` and `toolEnglish(action)` read it, the second through `tEnglish`, so the palette, the harness
and the guide still find a tool by its English name.

A group's `label` is an id such as `CREATE`, code matches on it, and `groupName(id)` gives the text to show. Match on the
id or the action, never on a shown label.

A tool name is a glossary term and reads the same wherever it shows, so tools with the same English name share one key
(Scale, Linear Pattern and Rect Pattern). This is an exception to the rule above that the same English in two places
gets two keys. A language that needs two words gives one of them a new key, the old key keeps working. A family named
like its first tool (Revolve, Move, Shell, Rectangle) reuses that tool's key, because the rail hides the family's
sub label when it equals the tool's label, and a shared key keeps that true in every language. Plugin tools keep the
plugin's own words.

The rail's selection offers (`src/ui/selectionTools.ts`) name an app tool through `toolLabel(action)`, so Fillet reads
the same with an edge selected as in the Modify flyout. A plugin tool, even one that claims an app tool's id, keeps
the plugin's label.

The rail pill is at most `14rem` wide and its labels wrap, so a long translated name grows the pill taller and is never cut.

## Selection words

The selection readout under the rail, what it announces, Describe selection (`src/app/describeModel.ts`) and the
refusal a list row gives when a tool waits for another kind of pick all read through `t`. A line that only counts
reuses the rail's `rail.count.*` through `countLine` in `src/ui/selectionTools.ts`.

A lone picked face, edge or plane is a list of whole fact lines. On screen they join with ` · `, aloud they join
through `pick.list.more`, so each language chooses its own break. A fact has one key that renders every channel with an
`as` select, which keeps the screen and the voice from drifting apart. Never join translated pieces into a sentence.

`treePickRefusal` in `src/ui/treePick.ts` takes a `TreePickWant`, never a phrase, so the caller names no noun and the
language builds the whole line.

## Stress results

The Stress Results tab, its legend, its status lines and what it announces read through `t`. The verdict
(`src/ui/stressVerdict.ts`), the result rows and details (`formatStressResult` in `src/ui/stress.ts`), the legend ramps
and the undo and redo labels (`src/ui/stressHistory.ts`) are getters or functions over the reply, so the tab follows a
language switch with no new run. A row is never spread or copied, because a copy keeps the language it was made in and
loses its getter. The pins on the part are relabelled by the language listener in `src/ui/panels.ts`.

The engine's warning text stays English on the wire, MCP callers read it too. `src/ui/stressWarnings.ts` matches it with
a regex per warning and maps each match to one message key with named arguments, so a sentence is one ICU line and a
count is a plural. A warning no rule matches shows as the engine sent it. A new rule comes with a case in
`tests/ui/stressWarningsDrift.test.ts` that names the Rust literal it matches, so a reworded engine warning fails a test
instead of falling through to English.

Numbers cut out of engine text go through `markDigits`, never `Number`, so English keeps the engine's digits and a
language with a decimal comma gets its mark. Material names and the names the user typed for a load or a support are
data and stay as typed, only the words around them translate. A caution word keeps its strength in every language, a
verdict that says it may fail never says it fails.

## Shortcuts

The Keyboard Shortcuts window (`src/components/overlays/ShortcutsDialog.vue`) and its key button
(`src/components/ui/KeyCapture.vue`) read every line through `t`. The rows come from `src/input/shortcuts.ts`, which
gives each action one line: a tool or command row names the same key the rail and the palette use, so Fillet reads the
same everywhere. A row's label is read when the window builds its groups, never stored in the row, so a copy of a row
made before a language switch still shows the new language.

- Key names are not translated. `formatShortcut` builds the ids of the saved keys (`action|context|Ctrl+Shift+X`), so
  its output never changes with the language, and the window shows keys as the menus and the palette do. A language
  that wants another word for a key changes `fmtKeys` only.
- Spoken key names are translated, `keys.spoken.*`, so a screen reader says the words of the chosen language.
- Search matches the shown name and the English one, built with `tEnglish`, so an English name still finds a row.
- `bindingRows`, `checkShortcut` and the problem strings plugins can read stay English. The window translates them at
  its edge, a refusal it knows by its exported constant and a name from `RESERVED` through `reservedLabel`.
- A plugin's keymap row follows the language when its label is a getter, see [PLUGINS.md](PLUGINS.md).

`tools/harness/tests/browser/test_shortcuts_language.py` opens the window in German and Pseudo at 1024x600, on every
page and with a conflict line open, and checks nothing is cut.

## Wording

Plain words close to the English tone, and the manual's voice (`docs/DESIGN.md` section 9). Formal address: Sie,
vous, usted, 您, and the です and ます forms. No em or en dashes and no spaced hyphen as punctuation, in any language;
`scripts/check-repo-hygiene.sh` refuses the dashes in the language files too. Each language keeps a glossary,
`src/i18n/glossary/<code>.json`, of the words it uses for FundaCAD's terms, with a note where one word was chosen
over another; check it before translating a line and add a term when a new one comes up. The app never reads it.
Notes never name another product.

## Add a language

1. `src/i18n/locales/<code>.json` with every English line. The code follows `LANGUAGE_CODE` in
   `src/i18n/languages.ts`: a lowercase language, then an optional script and region, as in `pl`, `pt-BR` or `zh-CN`.
2. A row in `SHIPPED` in `src/i18n/languages.ts`. `native` is the language's name in its own words, `machine` is
   "machine translated" in that language, shown beside the name in the picker, `bcp47` is the page's `lang`, and
   `followsSystem` is `false`. Drop `machine` once a person has read the whole file.
3. `src/i18n/glossary/<code>.json`, shaped like the others.
4. The language in the two tables of shipped languages in `tests/i18n/locales.test.ts`.

`followsSystem` decides whether System picks the language for a computer set to it. It stays `false` until all
of the app's text goes through `t()`, so nobody gets an app half in their language without asking. Before turning it
on for the first language besides English, give every e2e script that starts a browser a locale. A Traditional
Chinese system gets English until a Traditional file ships, and Simplified Chinese is only ever picked by hand.

## Your own language file

A user corrects single lines, or adds a language FundaCAD does not ship, with a file in the same format named by
its code. Each line is looked up in the user's file, then the shipped file, then English, and a line that does not
read falls through to the next. A file for another language (`pl.json`) adds `polski (your file)` to the picker,
its missing lines in English. A regional file such as `de-AT.json` takes its missing lines from the shipped base
language, here German; `zh-TW.json` finds no `zh.json` and stays on English. System never picks either.

- Desktop: `<app data>/languages/<code>.json`, `<app data>` being `%APPDATA%\dev.fundacad.app` on Windows,
  `~/Library/Application Support/dev.fundacad.app` on macOS and `~/.local/share/dev.fundacad.app` on Linux
  (`dev.fundacad.app.dev` for FundaCAD Dev). The Language card's Open folder makes and opens it, and Reload reads it
  again; nothing watches it. The three commands in `src-tauri/src/languages.rs` are the only way in: they take a
  code checked against the same pattern, never a path, open a file without following a link, and read at most
  256 KiB of UTF-8. A refusal for size or encoding starts `too-large:` or `not-utf8:`, which the card names; any
  other refusal reads as not read. In safe mode they read nothing.
- Browser: the card's Load file… keeps the text in `localStorage` (`fundacad.language.dropin.<code>`), and it is
  checked again at every start.

Shipped and dropped in lines pass the same checks, `checkLine` and `parseOverrides` in `src/i18n/overrides.ts`: a
flat JSON object of strings (a leading BOM is fine) of at most 256 KiB, keys English has, at most 2000 characters a
line, not empty or blank, no tags or entities (also none a plural or select could put together from its parts), no
control, separator, tag or text direction characters (LRM, RLM, ZWJ and ZWNJ are fine), a message that reads, and
only values the English line uses. A line that fails is listed in the card with the reason, the rest of the file
still works. A dropped in file cannot change the card's lines about itself (`prefs.language.system`, `systemYours`, `yours`,
`inUse`, `skipped`, `skip`, `more`, `remove`, `safeMode` and `error.*`), and the picker marks any language, shipped
or not, whose file is in use. A code is never `con`, `prn`, `aux` or `nul`, which Windows opens as a device.

A line for a plugin has the key `<plugin id>:<key>`, for example `"Acme.Rivets:menu.file.send": "..."`. It is
read only by that plugin (the id is matched without regard to case), can never change a core line or another
plugin's line, and counts as a line in use in the Language card. The text checks above apply, the argument check
runs when the plugin looks the line up, against the plugin's own English, and a line with an extra value is
skipped there without a note in the card. An older app lists these keys as unknown lines and reads the rest.

## Plugin lines

A plugin ships its own lines (menus and tools are described in [PLUGINS.md](PLUGINS.md)) in `plugins/<id>/locales/<code>.json`, with `en.json` complete, and reads them with
`pluginText` from `fundacad` (`src/i18n/pluginLines.ts`). The core's `t` is not available to a plugin and a plugin
never uses a core key.

```ts
import { pluginText } from "fundacad";

export const { t, tEnglish } = pluginText<typeof import("./locales/en.json")>(
  "Acme.Rivets",
  import.meta.glob("./locales/*.json", { eager: true, import: "default" }),
);
```

The eager glob puts the files into the plugin's one code file. Keys follow the core pattern, `area.thing`, and
live in the plugin's own namespace. Each line is looked up in the user's `<id>:<key>` line, then the plugin's
file for the language, then for its base language (`de-AT` reads `de`), then the plugin's English, then the key
itself. Plurals and numbers follow the language, the English fallback keeps English plurals. Under Pseudo
(dev builds) the plugin's English is stretched like the core's.

A plugin's files are untrusted. A file of more than 256 KiB or more than 2000 keys is ignored whole, and a line
with a bad key, a value that is not text, or one that fails the checks of the user's file is dropped, each with
one console warning. Nothing throws. `t` reads the active language, so a getter or computed that calls it follows
a language switch. A plugin with no locales folder works as before, in English.

## The strings guard

`node scripts/check-ui-strings.mjs` runs in CI and fails on new UI text outside `t()`: text and text attributes in
templates, and TypeScript strings passed to a UI call, set as a text property (`label`, `hint`, `title` and the
like) or that read as a sentence. `scripts/ui-strings-allow.json` counts the raw strings each file held when the
guard came, per file and kind (`template`, `script`). A file over its count fails with the line and text of each new
string. After converting text, `node scripts/check-ui-strings.mjs --lower` lowers the entries; it never raises one.
Raise an entry only by hand, with a reason, for text that must stay as it is.
A menu row that follows the language keeps its English text as `refName`, the name refs, plugins and the harness
find it by, so `src/app/menubarDef.ts` keeps an entry for those names.

## Pseudo

In a dev build (`npm run dev`, which the harness uses as well) the picker offers Pseudo: each line accented, about
1.7 times as long and between brackets, so `Add face` reads `[ÅÅddd fááççééé]`. A line without brackets has not gone
through `t()`, and a missing closing bracket means a label is cut. A control that does not fit beside its label
wraps to its own line, the rule of `FieldRow` and `.stress-field` (`wrap-row` in `src/styles/ui/_field-row.scss`), it is
never cut. The harness's `test_text_size.py` picks Pseudo in
Preferences, Appearance, then reads every screen of its walk in Pseudo with Comfortable text on, and fails on a cut
control or small text. Production builds never offer Pseudo, and a stored Pseudo reads as System there.
