# Languages

FundaCAD's text lives in one file per language, `src/i18n/locales/<code>.json`. English (`en.json`) is complete
by definition and is the fallback for every line. Each other shipped language holds every English line, machine
translated until a person reviews it. How a user picks a language and corrects a line is in the manual
(`manual/docs/reference/preferences.md`); this page is for contributors.

Saved files, the engine, MCP tools and their schema, the start question window and the manual stay English. So do
the tests: a test that never calls `initLanguage` sees English, and the harness `Session` and `e2e/docs_shots.cjs`
run the browser in `en-US`.

## Show a line

1. Add the line to `src/i18n/locales/en.json`, keeping the file sorted by key, two space indented, with a newline at
   the end. `tests/i18n/locales.test.ts` checks the format.
2. Add the same key, translated, to every other file in `src/i18n/locales/`. Machine translation is fine (see
   Wording below); a shipped language that misses a line fails the tests.
3. Show it with `t()`, imported by name:

```ts
import { t } from "../../i18n";

t("stress.setup.addLoad");
t("stress.faces.count", { n: faces.length });
```

The key's type is made from `en.json` (`MessageKey` in `src/i18n/index.ts`), so a key with no English line fails
`npm run typecheck`, in templates as well as in TypeScript. Write keys as literals, never build one
(`` t(`stress.dir.${d}`) ``), since a built key escapes that check; a table maps a value to its key, as `AXIS_KEYS`
in `src/ui/stress.ts` does. A key no source names in quotes fails the tests, so when the code stops asking for a
line, remove it from every file.

`t()` reads the chosen language reactively: a template or a `computed` shows the new text the moment the language
changes. A table built once when its module loads does not. Give its labels a getter, as `option()` in
`src/ui/stress.ts` does, or build the list in a `computed`. Text drawn outside Vue, on a canvas or in a menu built
once, listens with `onLanguageChange`.

## Keys

- `area.thing` or `area.thing.detail`, each part a lowercase letter then letters and digits: `prefs.language.hint`,
  `stress.setup.forceDirection`. The area is the feature or panel.
- The same English in two places keeps two keys, another language may need two different words.
- Keys are the API of every user's own language file. A typo or wording fix keeps the key. A changed meaning gets a
  new key, so a translation of the old meaning falls back to English instead of saying the wrong thing. A user's
  line for a key that no longer exists is listed as skipped, never fatal.

## Messages

Lines use a small part of ICU MessageFormat (`src/i18n/format.ts`), never pasted strings, so each language puts its
words in its own order and forms its own plurals.

| Form | Example | Notes |
|---|---|---|
| Value | `{body} (not on the current model)` | Shown as given. A missing one shows as `{body}`, so it is seen |
| Number | `{missing, number} not found` | Formatted for the language, never grouped: `210000` |
| Plural | `{n, plural, =0 {No faces} one {# face} other {# faces}}` | `#` is the count. Options `zero one two few many other` and `=N`, `other` required |
| Choice | `{reason, select, markup {holds markup} other {not used}}` | Any word as an option, `other` required |

```json
{
  "stress.faces.count": "{n, plural, one {# face} other {# faces}}",
  "stress.faces.missingSome": "{n, plural, one {# face} other {# faces}}, {missing, number} not found on the current model"
}
```

Each language fills the plural options its own way: French reads 0 as `one`, Chinese and Japanese need only `other`.
A translation may leave out a value English uses, never add one English lacks. An apostrophe quotes: `'{'` shows a
brace and `''` one apostrophe, while an apostrophe before a letter stays as it is, so `l'appui` needs no doubling.

A number shown beside a value box is passed as text, formatted by the box's own code, not as `{n, number}`, so a
panel never shows `0,35` beside a box that reads `0.35`. Counts and prose take `{n, number}` and plurals.

## Text, never markup

A line is text. Never put a `t()` result in `innerHTML`, `v-html` or any other HTML sink, set `textContent` or use a
template. A user's language file is untrusted, so lines with tags or entities are refused, but the sink is the real
guard.

## Values are not labels

Translate what is shown, never what is saved or compared. An option's value stays as it is (`"Custom"`, `"fixed"`),
only its label goes through `t()`. Material names (`PA12 nylon`, `steel S235`), default feature names (`Box`) and any
other name that lands in a document stay English. `tests/i18n/stressSetup.test.ts` checks that a study set up in
German equals the English one; a panel that saves what it shows wants the same test.

## Wording

Plain words close to the English tone, and the manual's voice (`docs/DESIGN.md` section 9). Formal address: Sie,
vous, usted, 您, and the です and ます forms. No em or en dashes and no spaced hyphen as punctuation, in any language;
`scripts/check-repo-hygiene.sh` refuses the dashes in the language files too. Each language keeps a glossary,
`src/i18n/glossary/<code>.json`, of the words it uses for FundaCAD's terms, with a note where one word was chosen
over another; check it before translating a line and add a term when a new one comes up. The app never reads it.
Notes never name another product.

## Add a language

1. `src/i18n/locales/<code>.json` with every English line. The code follows `LANGUAGE_CODE` in
   `src/i18n/languages.ts`: a lowercase language, then an optional script and region, as in `pl`, `pt-BR` or `zh-CN`.
2. A row in `SHIPPED` in `src/i18n/languages.ts`. `native` is the language's name in its own words, `machine` is
   "machine translated" in that language, shown beside the name in the picker, `bcp47` is the page's `lang`, and
   `followsSystem` is `false`. Drop `machine` once a person has read the whole file.
3. `src/i18n/glossary/<code>.json`, shaped like the others.
4. The language in the two tables of shipped languages in `tests/i18n/locales.test.ts`.

`followsSystem` decides whether System picks the language for a computer set to it. It stays `false` until all
of the app's text goes through `t()`, so nobody gets an app half in their language without asking. Before turning it
on for the first language besides English, give every e2e script that starts a browser a locale. A Traditional
Chinese system gets English until a Traditional file ships, and Simplified Chinese is only ever picked by hand.

## Your own language file

A user corrects single lines, or adds a language FundaCAD does not ship, with a file in the same format named by
its code. Each line is looked up in the user's file, then the shipped file, then English, and a line that does not
read falls through to the next. A file for another language (`pl.json`) adds `polski (your file)` to the picker,
its missing lines in English. System never picks it.

- Desktop: `<app data>/languages/<code>.json`, `<app data>` being `%APPDATA%\dev.fundacad.app` on Windows,
  `~/Library/Application Support/dev.fundacad.app` on macOS and `~/.local/share/dev.fundacad.app` on Linux
  (`dev.fundacad.app.dev` for FundaCAD Dev). The Language card's Open folder makes and opens it, and Reload reads it
  again; nothing watches it. The three commands in `src-tauri/src/languages.rs` are the only way in: they take a
  code checked against the same pattern, never a path, open a file without following a link, and read at most
  256 KiB of UTF-8. In safe mode they read nothing.
- Browser: the card's Load file… keeps the text in `localStorage` (`fundacad.language.dropin.<code>`), and it is
  checked again at every start.

Shipped and dropped in lines pass the same checks, `checkLine` and `parseOverrides` in `src/i18n/overrides.ts`: a
flat JSON object of strings (a leading BOM is fine) of at most 256 KiB, keys English has, at most 2000 characters a
line, no tags or entities, no control or text direction characters, a message that reads, and only values the
English line uses. A line that fails is listed in the card with the reason, the rest of the file still works.

## The strings guard

`node scripts/check-ui-strings.mjs` runs in CI and fails on new UI text outside `t()`: text and text attributes in
templates, and TypeScript strings passed to a UI call, set as a text property (`label`, `hint`, `title` and the
like) or that read as a sentence. `scripts/ui-strings-allow.json` counts the raw strings each file held when the
guard came, per file and kind (`template`, `script`). A file over its count fails with the line and text of each new
string. After converting text, `node scripts/check-ui-strings.mjs --lower` lowers the entries; it never raises one.
Raise an entry only by hand, with a reason, for text that must stay as it is.

## Pseudo

In a dev build (`npm run dev`, which the harness uses as well) the picker offers Pseudo: each line accented, about
1.7 times as long and between brackets, so `Add face` reads `[ÅÅddd fááççééé]`. A line without brackets has not gone
through `t()`, and a missing closing bracket means a label is cut. A control that does not fit beside its label
wraps to its own line, as `.stress-field` in `src/styles/_stress.scss` does, it is never cut. Production builds
never offer Pseudo, and a stored Pseudo reads as System there.
